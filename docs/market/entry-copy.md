- 「支持任意桌面端」——只有实现过协议模块的供应商才成立（当前两家）。

## 2. 详情正文

```
把本机桌面客户端里**已经登录、已经付费**的模型，接进 DSH 的模型选择器。

装完之后，Loomy（讯飞办公助手）和商汤小浣熊（Raccoon）的模型会出现在同一个模型选择器里，
像用其它模型一样直接对话；旁边的胶囊显示这家客户端**所有账号**还剩多少额度（合计）。

## 它做什么

- 读取本机桌面端已经存在的登录态，把模型目录注册进 DSH。
- 对话、流式输出、思考过程（thinking）按原样透传。
- 一个供应商下可以放多个账号，随时切换；可开启「每次调用随机选一个健康账号」。
- 胶囊显示所有账号的合计，账号抽屉与设置卡片只读展示逐账号余额与明细。
- 支持把账号导出成一段文本，粘到另一台电脑导入，免收一次验证码。
- 诊断页可以一键复制报告，也能对上游发一次真实的连通性探测。

## 它不做什么

- 不提供账号，不代注册、不代开通、不绕过计费：每次对话扣的都是你自己账号的额度。
- 不把凭据上传到任何服务器，也没有中转：插件只在本机读写桌面端自己的登录文件。
- 不替桌面端刷新令牌：登录态过期时只给可执行的提示。
- 不做跨供应商的余额合并——两种额度不是同一种货币，合并会误导。
- 不写回桌面端的登录文件。

## 装之前

1. 电脑上装了对应的桌面客户端，并登录过一次（插件读的是它保存的登录态；登录一次就够，之后不必常开）。
2. 电脑上装了 DSH（`0.2.2-rc.1` 或更高）。

两家供应商互相独立：**没装或没登录的那一家不会出现在模型选择器里**（避免选到一个必然失败的
分组），设置卡片里仍会列出它并写明原因，点「重新检测」即可。一家出问题不影响另一家。

## 从 0.2.x 或更早版本升级

0.3.0 是**破坏性变更**：插件内部把「一家供应商」变成了契约，因此数据与配置都换了位置。

- **需要重新登录一次**。数据目录变为 `~/.dsh/storages/dsh-connect-desktop/<供应商>/`；旧目录
  `dsh-connect-loomy/` 不再读取（有意为之：不做双读、不留迁移代码）。
- **配置改为按供应商分组**：`vendors: { loomy: { baseURL }, raccoon: { baseURL } }`，缺项自动回落到默认值。
- **路由与 CSRF 头统一**：`/plugins/dsh-connect-desktop/<供应商>/…`，CSRF 头只有一个 `x-dsh-connect-csrf`。
- 聊天记录不受影响：模型标识（`provider='loomy'` / `'raccoon'`）刻意冻结。

升级方式是两个粘贴块，顺序不能颠倒：

先 `dsh plugin --profile web remove dsh-connect-loomy`，再安装本条目。

## 安全与隐私

- 登录态只在本机读取，导出包等同于密码，请勿外发。
- 账号信息（手机号、用户 id）在本机界面上**原样显示**，方便你核对自己用的是哪个号；它们不出现在任何日志里。
- 诊断报告可一键复制，内容含版本、路径与上游原话，不含登录态令牌。
- 卸载即断开：删掉插件不会留下后台进程，也不会改动桌面端的数据。
```

## 3. 关键词

```
dsh-plugin, deepseek-harness, desktop-client, model-provider, loomy, iflytek, raccoon, sensetime, multi-vendor
```

取舍：

- `desktop-client` 是这一类别词，也是与名称相近的其它实现区隔的主要抓手。
- `raccoon` / `sensetime` 覆盖第二家供应商的中英文两种搜法（用户可能搜「商汤」「小浣熊」「SenseTime」）。
- `multi-vendor` 点明"一个插件接多家"这个核心能力。
- 保留 `loomy` / `iflytek`：老用户仍在按旧名搜，关键词里留着才能被找到；但**标题与描述里不再出现旧名**（除「从旧版本升级」那一段）。
- 不写 `free`、`unlimited`、`api-key`、`proxy`：既不符合事实，也会把搜索意图引向错误的人群。

## 5. 旧条目需要追加的指向说明

追加到现有 `dsh-connect-loomy` 市场条目**描述末尾**（原有内容保留，段落前留一个空行）：

```
---

本项目已更名为 **DSH Connect Desktop**（包名 `dsh-connect-desktop`）。新版本、新供应商与后续
更新都只在 https://github.com/diudiu62/dsh-connect-loomy 发布（仓库名可能稍后改名，旧地址会自动跳转）。

请注意两点：
1. 0.3.0 起是破坏性变更——升级后需要重新登录一次，旧的账号数据目录不再读取；
2. 市场上可能存在与本项目同名的第三方实现，功能与数据来源都无关。请认准上面的仓库地址，
   不要仅凭包名判断装的是哪一个。
```

为什么写这段而不是只写「已改名」：改名之后旧名会留给市场上其它实现，用户搜旧名时最容易被引到
别处；只写「已改名」等于把判断责任推给用户，写明「可能指向其它实现 + 认准地址」才可判定。

如果条目描述有长度上限、放不下整段，优先保留这三句，按顺序删减：

1. `已更名为 DSH Connect Desktop（dsh-connect-desktop）`
2. `0.3.0 起需重新登录一次`
3. `旧名条目可能指向同名第三方实现，请认准仓库地址`
